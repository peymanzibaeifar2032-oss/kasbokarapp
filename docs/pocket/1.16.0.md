# Pocket 1.16.0-test (versionCode 26): stability, data safety, security and calendar fixes

Built from branch `pocket/app-1.16.0`. Same package (`com.peymanzibaeifar.tattoobooking`, test variant `.test` like every published `-test` APK), same minSdk 26 / targetSdk 34, same signer as 1.15.3-test (`be4b8113…6ed5e`), so it installs as an update over 1.15.3-test and keeps all data.

## Reference source (1.15.3-test)
- The published 1.15.3-test APK (`f6b7d289…c880`) was built from commit `9c89409` **plus one uncommitted line** in `src/lib/save.ts` (`saveAction` attaches the HTTP status to its error). That line is now commit `b1c9bbe`, the first commit of this branch.
- Proof: rebuilding that source gives a byte-identical `assets/pocket/assets/pocket.js`, `index.html`, `pocket-offline.html` and fonts; identical `AndroidManifest.xml`, `resources.arsc`, icons and `classes2.dex`; and app bytecode (`com.peymanzibaeifar.tattoobooking.*` in dexdump) identical. `classes.dex`/`classes3.dex` differ only in how debug D8 packs library classes into files.
- Documented differences: `smoke.html` in the old APK was an untracked QA file (not app code; not shipped now). `style.css` from a clean checkout of `9c89409` has extra, unused Tailwind utilities (Tailwind scans the whole repo) — no Pocket class changes.

## Fixes
**Data safety**
- Bulk saves (bookings, cash box, trainees, trainee payments) could commit the `clear()` and lose every row when one row failed to store. The transaction is now aborted on any write error, so the previous data stays intact (new `storage-safety.test.ts`; it fails on 1.15.3).
- A download merges into the bookings stored *now*, not the list captured when the button was tapped. An edit made during a slow download is no longer overwritten.
- Saving a new appointment twice (double tap or retry after an error) no longer creates two rows: the id is reserved once per open form. The cash-box form works the same way. Trainee writes run one at a time.
- Move/delete/cash/trainee write errors (storage or license lock) now show a message instead of failing silently or showing "saved".
- Import with «جایگزینی موارد هم‌شناسه» asks for a second confirmation. Optional: restore language/profession from the backup file.
- The cash tab no longer shows the previous download's status while a new one runs.

**Calendar**
- Jalali leap-year bug: Esfand of leap years (e.g. 1403, 1408) had 29 days instead of 30, so 30 Esfand was missing from the calendar and rejected by backup validation. Fixed in `src/lib/calendar/jalali.ts` (shared with the website, same fix applies there).
- English UI now shows a real Gregorian month (Sunday first, LTR, English month names); bookings still use the Jalali day key, so switching language keeps every appointment on the same day.

**Network / weak connection**
- No network: download/check/license calls stop immediately with a clear message (no long wait); the account is re-checked when the phone comes back online.
- focus + visibilitychange + resume used to send up to three account checks at once; now one.
- Native read-only calls (`studioPocketAccess`, `studioPocketExport`) retry once after a dropped/timeout connection. Busy/offline replies show real reasons instead of a generic error.

**False "install the new version" prompt**
- The JS bridge used to be removed/re-added in `onPageStarted`; Android applies that only on the *next* page load, so after visiting another page the app's own page could lose the bridge and show «نسخهٔ جدید اپلیکیشن را نصب کنید». The bridge now stays installed and every method checks the current page origin. Messages no longer ask for a new version.

**Security**
- Bridge methods refuse calls when the main frame is not the Pocket offline page or kasbokarapp.com (previously a third-party page could still reach them for one load).
- Saved website passwords (site login autofill) are encrypted with an Android Keystore AES-GCM key; old plaintext entries are re-encrypted on first use. These methods answer only on kasbokarapp.com pages.
- The exported activity no longer opens any URL passed in the `open` extra by another app; only kasbokarapp.com.
- `openExternal` uses the same safe scheme rules as page links (no `intent:`/`file:`/`content:`).
- WebView camera/microphone requests are denied (the app has no such permission); `file://` access is off.
- Logs: no page URLs with query strings, no console messages (customer data/tokens) except truncated JS errors in debug builds.
- Owner access still depends only on the server's answer to the site session (`studioPocketAccess`); the offline email grants nothing.

**Owner activation**
- When the server confirms the signed-in site account is the owner, the app requests the owner's self license automatically (once per session). The owner is not asked for a code.
- Other tabs show a slim notice instead of the full activation form; the full form is in «پشتیبان».

**Stability / speed**
- A crashed WebView renderer is replaced by a fresh activity (the old code reloaded the dead WebView, which crashes); WebView is destroyed in `onDestroy`.
- PDF list export (`saveReport`) runs off the UI thread (no ANR on long lists).
- Sorting rows with missing optional fields from old backups can no longer crash the calendar.
- User agent reports the real app version.
