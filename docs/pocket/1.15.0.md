## How licensing behaves
| State | What works | What is blocked |
|---|---|---|
| Valid (code or owner self-license) | everything | — |
| No license / expired / revoked / invalid / offline lease over / clock rolled back | viewing all data, call / SMS / WhatsApp / Instagram links, gallery view, JSON export, PDF, activation, owner sign-in, "check again" | new/edit/delete bookings, cash entries, trainees & payments, JSON import, "restore previous import", loading/merging from the site |

- Gate is at the storage layer (`assertCanMutate()` in savePocketBookings, saveCashEntries, applyServerFinance, saveTrainees, saveTraineePayments, commitBackup) plus an early check before server download. UI shows the reason; nothing is deleted.
- Offline lease: token `olu = min(expiry, server_now + lease)`. Default lease 72 h, owner sets 1–168 h per license. Online refresh every 6 h when the app is opened/focused. Revocation applies at the next online refresh or when the lease ends — not instantly offline.
- Clock: server `iat` + the highest trusted time seen; >10 min rollback blocks edits until fixed or refreshed online. A rooted/modified APK can bypass any offline check (honest limit).
- Device binding: SHA-256 of a random install secret (no hardware IDs). Cap default 1, owner-editable 1–20, enforced atomically on the server. Owner can "release" a device.
- Codes: 20-char Crockford base32 (100 bits), shown once in the owner panel, stored only as HMAC. 10 activation attempts / 10 min / IP. Unknown and revoked codes get the same answer.
- Owner's own phones: "ورود صاحب برنامه" → website login in the app → server-verified owner session issues a self license (5 devices, 1 year, auto-extended, not revocable from the panel). No email-only bypass.
- Old releases (≤1.14.4) are unaffected; there is no server switch that locks all apps.
- License token, install secret and trusted-time are in localStorage keys `pocket.license.*` / `pocket.install.*`; they are NOT in JSON backups (checked by test) and JSON import cannot set them.

## Runtime secret / key
- Private key: generated on the server at first use, stored only AES-256-GCM-wrapped with an HKDF key from the existing runtime secret (`BETTER_AUTH_SECRET`, or `POCKET_LICENSE_KEY_SECRET` if set). Never in APK, repo, Netlify, exports or logs. `POCKET_LICENSE_SIGNING_KEY_PEM` env is supported as an override.
- If the runtime secret ever changes, the server fails closed (issuing/refresh return 503 "unavailable") instead of re-keying; existing offline leases keep working until they lapse. Recovery = restore the secret, or rotate: ship an APK pinning the new kid first.
- Weekly DB backup artifacts contain only the wrapped key.
