# Pocket 1.16.1-test (versionCode 27): site design image (عکس طرح) in the appointment card

Built from branch `pocket/app-1.16.1` (on top of 1.16.0). Same package (`com.peymanzibaeifar.tattoobooking.test`), minSdk 26 / targetSdk 34, same signer as 1.16.0-test (`be4b8113…56ed5e`), so it installs as an update and keeps all data.

## Root cause
1. The app's export parser kept only fixed booking keys plus `serverDetailsSchema`. So the `photo` field that server commit `8d86bc7` added was dropped, and the merge always kept `existing.photo`. The `8d86bc7` app-side edit went into `main`'s old web copy of `pocket-book.ts`, which is not the APK source, and no APK was rebuilt.
2. The server sent only `reference_images[0]`, and only when it was an inline data URL of 300k characters or less. Customer uploads are stored as `/api/tattoo-file?id=<uuid>`, so they never arrived.
3. Inline images are also unsafe. The Android client caps a response at 4 MB, so a dozen designs in the export could fail the whole sync.

## Fix
- **Server (PR #34):** the export now sends only a `photoKey` per booking. A new owner-only, read-only action, `studioPocketPhotos`, returns at most 8 images per call. It resolves both panel data URLs and customer files (a file only inside its own request), with a cap of 1 MiB per image and 3 MiB per response. Any remainder comes back as `deferred`.
- **App:**
  - The parser keeps `photoKey`.
  - After a successful owner download, images are fetched 4 at a time and cached in a separate IndexedDB (`tattoo-pocket-photos`). The bookings and cash databases are untouched.
  - Images already cached with the same key are not fetched again.
  - The cache is never cleared by a sync, so a design stays visible offline.
- **Native:** a new bridge method, `downloadPocketPhotos(requestId, idsCsv)`. It uses a fixed action, ids validated in Java (at most 8), the same origin check, and the same cookie-only-to-kasbokarapp.com rule.
- **UI:**
  - The appointment card shows a thumbnail with a «نمایش طرح» button.
  - The button opens a full-screen viewer with «بزرگ‌نمایی» (zoom; a double tap also toggles it) and «بستن».
  - A phone-added photo opens in the same viewer.
  - If the site has a design that is not cached yet, the card says so and asks to download again. A failed image request never touches appointments.
- **Not owner, or a contact/local license:** the server refuses the export (403), so no image request is ever made.
